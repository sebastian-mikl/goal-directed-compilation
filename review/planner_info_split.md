# The informed planner prompt: what was taken from GDC's prompt, line by line

Generated by `scripts/planner_info_prompt.py --write-split` for the equal-information run (`review/planner_info_prereg.md`). For each database, every line of GDC's recorded prompt is listed with its class and a one-line reason:

- **keep:** domain information, sent as written, except that column identifiers are renamed (see below).
- **mixed:** domain meaning written in Goal format. Only the domain part is sent, and the line is shown both ways.
- **out:** GDC's output format: task framing, JSON instructions, the Goal schema, the OrderSpec and the CONTRACT rules on Goal fields.

**Column names.** GDC's prompt names each column by its schema-bridge identifier (`gdc/schema_bridge.AliasMap`, for example `annual_salary`). The planner's steps address the register's own columns, which its prompt lists verbatim. So in every kept or mixed line, a column identifier is written as the register's column, quoted as the planner's prompt quotes columns (`'Annual Salary'`), through the bridge's inverse map. Lines marked `→` were renamed this way. Nothing else in a kept line changes.

**Excluded on purpose.** The CONTRACT block includes rules on how to read a request, such as the scalar-aggregate, row-selection and implicit-ranking rules. Each of them is stated in Goal fields (columns, grain, derive, order, limit), and none states what a term or a value of the domain means, so all of them are out.

**Assembly.** The informed prompt is the reported planner prompt with its one occurrence of the shared briefing replaced by the kept and mixed lines, in GDC's order, with blocks separated by one blank line. The text before and after the briefing is checked byte for byte against the reported prompt: that is the planner's own instructions and its verbatim column list.
